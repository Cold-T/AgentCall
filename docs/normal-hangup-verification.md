# 正常通话结束修复

2026-10-06，用户报告真实 OpenAI 任务通话在意外的时间结束。检查用户最近的任务、通话状态和工具事件发现：

- 最新通话在 00:58:47 接通；最长时长为 300 秒。
- 模型在 00:59:09 调用 finish_task，随后在 00:59:10 调用 hangup。
- hangup 所在的 response 只有工具调用，没有实际音频。工具理由声称“致谢后结束”，但这段内部参数不会播放给对方。
- 手机在 00:59:13 报告 idle，实际通话约 26 秒；任务却记录为 audio_failed / Connection reset by peer。

上述时间为 America/Chicago。日志证明存在模型主动结束请求，未达到时长上限。SCO 与 HFP 分别报告状态；旧实现会在主动挂断后、HFP idle 尚未到达时，把正常关闭的 SCO 误当作任务失败。

## 改动

1. 任务指令明确要求：提交结果成功后，先实际说出结束语，再调用 hangup；工具 reason 是内部信息。
2. 任务执行器记录音频事件计数，提交结果后没有新音频的 hangup 被拒绝，并把“先口头告别再调用”的错误结果返回模型。仅有开场音频不能满足提交结果后的结束要求。
3. 没有结果时，正常挂断要求本次 response 已生成音频，例如错误号码的告别。异常、取消、超时仍按原流程清理。
4. 接受正常挂断后继续等待 response 完成、重采样尾部与 SCO 音频实际发送完成；不添加固定延迟、独立 VAD、插话策略或音频清空。
5. 向手机发送主动挂断指令时记录 task.hangup_requested；其后发生的 SCO 连接关闭不会抢占正常结果。主动挂断前的音频故障、蓝牙断连和模型错误仍分别保存。

检测音频保证模型不能只用无声的工具参数结束正常通话；结束语内容仍由模型根据任务指令生成。模型如何判断任务完成仍受目标与完成条件控制，程序没有增加额外聊天时长。

## 验证

152 项本地自动测试通过，Ruff 与格式检查通过。新增场景均覆盖 OpenAI 和 Gemini 的实际模拟协议：

- 开场 → finish_task → 无声 hangup：拒绝挂断，电话保持，模型生成新告别音频后重试；验证全部 300ms 模拟音频到达 SCO 后仅发送一次 AT+CHUP。
- 本地主动挂断时 SCO 先关闭、HFP idle 后到：最终 completed，无 audio_failed。
- 未请求挂断时音频先断：保持 audio_failed，已有模型 completed 结果不覆盖异常。

既有双向音频、工具去重、排队、超时、忙线、未接、模型故障、蓝牙断连与 API 取消挂断场景继续通过。修复未更改历史任务结果，未自动重拨用户号码；修复后的真实告别与挂断效果需要下一次用户主动通话复验。
